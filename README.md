1. **智能表情包解析**：大模型只需在自然语言回复中内嵌类似于 `:开心:猫猫:` 的标签，插件即可利用基于 Tag 的分级匹配与评分系统，自动将标签渲染并替换为对应的图片发送给用户。
2. **启发式自动偷图**：在用户或群聊发送图片时，异步调用一个多模态模型agent识图，后台静默评审图片是否为合规的“表情包/梗图”。若是，则自动提取特征标签并入库。

## ✨ 快速开始
启用插件，当你配置好至少一个可用的视觉理解LLM供应商后，即可在聊天中测试发送一个表情包。
然后在你的人格提示词里加一行类似这样的tip提醒bot使用表情包：“每次发言之前可以发一张能够表达自己心情的表情包。”

## 🧩 核心机制

在大模型需要发送一张代表当前情绪的照片时，不需要调用原生复杂的 Function Calling 发图工具，只需在聊天流中通过 **内置的 Markdown 风格冒号标签** 表达情绪。插件负责在 AstrBot 渲染链路层拦截，将标签平滑转换为最终平台支持的 `Image` 消息组件。

**表情包标签解析与评分系统：**
1. **输入提取**：大模型输出例如 `:开心:猫猫:`。
2. **逐级降级匹配**：插件会优先尝试“完整标签组合”命中；若没有结果，再按标签数量从多到少逐级回退查询候选资源。
3. **同级评分选优**：在当前命中层级内，按照精确匹配、首标签命中、字符串相似度、子串匹配等维度综合评分；若遇到同分情况，则结合历史使用次数与随机选择返回最终表情图。
4. **静默处理未命中标签**：没有匹配结果的标签不会原样展示给用户，而是直接从最终消息中移除。
5. **无感替换**：在用户侧展现的结果是一句文字加上一张顺滑衔接的表情图，甚至大模型自己都不知道图片的具体 URL。

## 📦 自动偷图与清理机制

插件内置了极具活力的**自动化库管策略**：

- **咕嘎严选**：默认状态下，自动偷表情机制只会针对带有平台表情特征字段的图片触发审查。对 NapCat / aiocqhttp 这类适配器，会优先读取原始图片段中的 `emoji_id`、`emoji_package_id`、`key` 等字段来识别 QQ 官方表情；若开启 `steal_all_images`，则所有图片都进入审查流程。
- **自动分类打标**：对收集到的图片使用内置 Prompt 的审查。如果判定为合法表情包，会将 LLM 总结出的标签 `Reason` 做归一化处理。
- **自动清理**：如果启用了自动清理功能并设置了存储上限，系统会周期性删除发送次数最少的表情包。

## ⚠️ 平台兼容性说明

- NapCat / aiocqhttp 场景下，QQ 官方表情通常会以带扩展字段的图片段上报，插件可以据此识别并自动审查。
- `qq_official` 适配器下的“超大表情”等特殊消息，当前 AstrBot 通常会把它们解析成类似 `<faceType=4,...>` 的纯文本占位，而不是 `Image` 组件。
- 在这种情况下，本插件拿不到真实图片，自然也无法完成自动偷图、图像审查或标签入库。这属于上游消息适配层限制，不是本插件单独能绕过的问题。

## 🛠️ 管理指令与配置示例

你可以通过对话直接执行以下指令对数据库里的表情包进行删除：

- `mood_check [数量]` —— 用于展示当前会话里最新触发的几条表情包资产记录（带 ID）。
- `mood_delete <asset_id>` —— 根据 ID 彻底删除错误偷取的或不想要的图片。

如果bot发了你不喜欢的表情包，先使用 `mood_check` 指令，随后会输出当前对话中历史发送过的表情包的名称 id 和 tag。看看你不喜欢的是哪一个，复制 `ID=xxxxxxx` 那一长串 ID，使用 `mood_delete xxxxxxx` 来删除。

当然你也可以通过直接删掉本地文件夹里的表情包来解决问题。每次插件启动时会自动检测数据库中文件不存在的表情包数据并清理掉。

在配置面板，关键字段解释如下：

```yaml
enable_auto_steal: true        # 是否启用自动偷取表情包功能
steal_all_images: false        # 若设为 true，则不再只处理QQ官方表情包，而是审查所有图片
enable_auto_cleanup: true      # 开启表情包的自动清理机制，删除x条使用次数最少的表情包
max_stickers_per_message: 1    # 控制每条消息最多被替换出几张表情包（避免模型抽风全是图）
max_prompt_tags: 30            # 每次注入给 LLM 的高频标签上限，避免提示词过长
```
