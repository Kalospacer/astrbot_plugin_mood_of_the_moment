此刻的心情

一个 AstrBot 表情包插件。大模型只需在回复里内嵌 :名称: 标签，插件就会在发送链路把它替换成对应的图片，让 bot 能用表情包表达心情。

v2 版本围绕两个概念工作：meme_def（一张图的唯一名字，用于精确选图）和 tags（多张图共享的分组标签，用于兜底匹配）。插件还提供自动偷图、去重、旧库迁移和一套 WebUI 管理面板。

核心概念

meme_def —— 精确选图

meme_def 是单张图片的全局唯一名称，和一张图片一一对应。当模型输出 :真冬_低头: 这样精确命中某个 meme_def 的标签时，插件直接发送那唯一的一张图。

tags —— 分组兜底

tags 是可以被多张图片共享的分组标签。当模型输出 :二次元: 或组合 :二次元:疲惫: 时，插件会在命中的分组里按评分逻辑挑一张最合适的图。

一句话区分：meme_def 指向唯一一张图；tag 指向一组图。模型不确定具体哪张图时用 tag 兜底，确定时用 meme_def 精确发送。

快速开始

  1. 启用插件，并在配置里选择一个可用的视觉理解 LLM 供应商（用于自动识图和命名）。
  2. 在 bot 的人格提示词里加一句提醒，例如：「每次发言之前可以发一张能够表达自己心情的表情包。」
  3. 正常聊天，模型会输出 :meme_def: 或 :tag:，插件自动替换为图片发送。

工具 API

以下三个工具由插件注册给大模型，模型在需要时通过 function calling 调用。你通常不需要手动触发——了解它们能帮你理解模型是如何查找和导入表情包的。

工具 mood_check_memes_def

按已知的 meme_def 精确查询一张表情包的视觉描述、tags 和发送 marker。模型在「不确定某个 meme_def 代表什么图」时调用它。

名称类型必填描述
meme_def string 必填 插件注入的唯一表情定义，例如 真冬_低头。

返回：该图的完整描述、tags、发送标记 :meme_def:；未找到时提示改用 mood_rough_search_memes 搜索。

工具 mood_rough_search_memes

根据自然语言在 meme_def、表情描述、分组 tags 和来源里模糊搜索候选表情包。模型在「想表达某种情绪但不知道叫什么」时调用它。

名称类型必填描述
query string 必填 想表达的动作、情绪、角色或使用场景，例如「疲惫」「捂脸」。
limit integer 可选 最多返回候选数量，范围 1–20，默认 8。

返回：候选列表（meme_def、tags、简述），按相关度与 meme_def 稳定排序。

工具 mood_steal_memes

导入一张图片进表情包库。必须提供唯一 meme_def、至少一个分组 tag 和视觉描述。模型在「看到一张值得收藏的表情包」时调用它手动入库。

名称类型必填描述
image_path string 必填 本地图片路径或 http/https 图片地址。
meme_def string 必填 这张图片的唯一定义，建议格式 角色_动作。
tags array<string> 必填 至少一个可被多张图片共享的分组 tag。
description string 必填 描述画面、情绪和适用场景。

返回：导入成功的 asset_id 与实际 meme_def；meme_def 冲突时自动追加 _2 后缀。

用户命令

这些命令由你直接在聊天里输入，用于管理表情包库。

命令 mood_check [数量]

展示当前会话最近触发过的几条表情包资产记录，带 asset_id、meme_def、tags 和使用次数。想找出 bot 刚发过的某张图时使用。

名称类型必填描述
数量 integer 可选 展示最近几条记录，默认 5，范围 1–20。
命令 mood_delete <asset_id>

按 asset_id 彻底删除一张不需要的图片资产（含数据库记录和图片文件）。需要管理员权限。

名称类型必填描述
asset_id string 必填 要删除的资产 ID，可由 mood_check 查得。
用法：先发 mood_check 找到不喜欢的那张图，复制它的 asset_id，再发 mood_delete <asset_id> 删除。

发送与解析

模型发图不需要复杂的工具调用，只需在文字里内嵌冒号标签。插件在 AstrBot 的渲染链路拦截并替换为 Image 组件。

每轮 Prompt 注入

插件在每次请求前动态注入当前库的表情索引，包含：全部 meme_def（受 max_prompt_meme_defs 限制）、全部 tags（受 max_prompt_tags 限制）以及使用规则。注入稳定排序、不随机。

解析顺序

  1. 标签是单个 token 且命中 meme_def → 精确发送唯一图片。
  2. 未命中 meme_def → 解释为 tag，单 tag 或组合 tag 走组合降级评分。
  3. 同分时按 meme_def 字典序稳定决胜（不引入随机）。
  4. 完全未命中 → 静默删除该标签。

自动偷图与清理

  • 咕嘎严选：默认识别「表情类型图片」触发审查，读取 emoji_id、emoji_package_id、sub_type、summary 等特征识别 QQ 商城表情。steal_all_images 审查所有图片；only_store_emojis 只处理商城表情。
  • 视觉识图协议：模型只输出一次 filename（规范化为 meme_def）、description、tags。meme_def 冲突自动追加 _2；不得与任何 tag 同名；缺字段拒绝入库。
  • 自动清理：达到存储上限后，周期性删除使用次数最少的表情包。

旧库格式化

v2 正常运行不读取旧数据库。WebUI 提供一次性的「格式化旧库」工具，用视觉模型重新识别旧库图片并迁移到新库。

  1. 预扫描与视觉分析：逐张调用视觉模型重新生成 meme_def、描述、tags，写入临时清单（不动正式新库），输出成功 / 失败 / 冲突报告。支持断点续传与部分提交。
  2. 确认提交：仅写入识图成功项，复制重命名图片、重建去重索引后切入新库，随后删除旧数据库与旧图片。失败项将被永久删除，确认页会明确提示。
也支持扫描 data/plugin_data/ 下其他插件的图片文件夹，把潜在的表情包图片导入进来。

配置参考

以下字段在插件配置面板中修改。

YAML 插件配置字段
字段类型默认说明
meme_review_provider_idstring留空用于识图审查与命名的 LLM Provider，留空用默认。
review_system_promptstring留空自定义识图 System Prompt，留空用内置 v2 协议。
max_stickersint100最大表情包数量，超过后不再自动采集。
max_stickers_per_messageint1每条消息最多替换出几张表情包。
max_prompt_meme_defsint30每轮注入的 meme_def 数量上限。
max_prompt_tagsint30每轮注入的 tag 数量上限。
enable_auto_stealbooltrue是否启用自动偷取表情包。
steal_all_imagesboolfalsetrue 审查所有图片；false 仅审查表情类型图片。
only_store_emojisboolfalsetrue 只审查商城表情，优先级高于 steal_all_images。
enable_auto_cleanupbooltrue是否开启自动清理。
cleanup_interval_hoursint1自动清理间隔（小时）。
cleanup_countint5每次清理数量。
min_stickers_to_keepint0清理时最小保留数量。

平台兼容性

  • NapCat / aiocqhttp：QQ 官方表情通常以带扩展字段的图片段上报，插件可据此识别并自动审查偷图。
  • qq_official：「超大表情」等特殊消息通常被解析成纯文本占位而非 Image 组件，插件拿不到真实图片，无法自动偷图或入库——这属于上游适配层限制。
